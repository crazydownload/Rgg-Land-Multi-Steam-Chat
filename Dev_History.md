## Подробно про ветку v26.x (игра + плашка + стена)

### v26.1 — определение игры из данных rgg.land (основа ветки)
- Скрипт читает встроенный пейлоад Next.js (`__next_f`) со страницы текущего эвента.
- Парсер регулярками собирает таблицу `ник → игра → онлайн`; онлайн-участники эвента получают игру **с сайта**, остальные — **fallback на Twitch**.
- Автоопределение сезона (`RGG Шашки · Сезон N` + даты; ветка `/games` для ЭГЛэнда) по `todayInRange`.
- Раскодирование `\uXXXX`, кэш 60 сек. Никаких захардкоженных ников.
- *Свойство источника (не баг):* данные — SSR-снапшот rgg.land, обновление ~раз в 60 сек.

### v26.2 → v26.4 — эксперименты со скрытием плашки (не основные релизы)
Плашка «сообщество/активность» вверху чата занимает место. Пробовали:
- **v26.2:** маска (пустая полоса ❌) → сдвиг iframe на 110px (работает, но прячет и акции).
- **v26.3:** плавающий сдвиг (прыгает поле ввода ❌) → плавающая маска (моргает ❌).
- **v26.4:** сдвиг + раскрытие по наведению на верх + удержание. Обнаружено: hover-действия списка сообщества недоступны в Twitch Embed в принципе (с v25) → цель «быстрые ЛС по участникам» недостижима.

> Зафиксированный урок: DOM чата Twitch — cross-origin, недоступен для инъекции. «Умные» синхронизации с внутренними виджетами невозможны; реально только статичный сдвиг или «не трогать».

### v26.5 — финал
**1. Плашка скрыта навсегда, без раскрытия.** Раз её действия в embed-чате бесполезны (отключены Twitch), а в режиме стены любой сдвиг/раскрытие двигает поле ввода на весь экран — плашка убрана статичным сдвигом чата вверх на 110px в обоих режимах. Вся hover-логика удалена; поле ввода никогда не двигается; код — один статичный `transform`.

**2. Стена: родной чат первого монитора (самая сложная часть).**
- *Проблема:* при открытой стене и смене стримера родной чат rgg.land вылезал поверх; плеер переключался со 2–3 клика. Причина: dock на первом мониторе не знал, что открыта стена (wall — отдельное окно).
- *Попытка 1:* флаг в localStorage → dock уважает стену, но сайт восстанавливал чат при React-рендерe.
- *Попытка 2:* `display:none` чату на каждом тике → **война с сайтом**, мерцание, сломанные клики ❌.
- *Попытка 3:* CSS `visibility:hidden !important` по селектору родного чата (`div.MuiPaper-root:has(twitch chat iframe)` — найден по чистому DOM при отключённом скрипте). Сайт не трогает `visibility`/`pointer-events` → нет мерцания. Но правило стало прятать и наш чат → «листочек» сломался.
- *Диагностика:* в `MuiPaper` с chat iframe нашего `#rggchat` нет никогда → CSS безопасен для нашего виджета. Настоящая причина «листочек не работает» — **залипший флаг** (`beforeunload` ненадёжен при закрытии крестиком/крашем).
- *Финал:* **heartbeat вместо флага.** Wall пишет `WALL_HB_KEY = Date.now()` каждую 1 сек; dock считает стену открытой, пока heartbeat свежий (< 3 сек). При любом закрытии heartbeat протухает → через ≤3 сек dock сам снимает `html.rgg-wall-active` → чат возвращается. Состояние самовосстанавливается, ничего не залипает. Родной чат прячется чисто через CSS, без мерцания; клики по стримерам с 1-го клика; «листочек» работает без стены.

## Зафиксированные уроки (чтобы не повторять)
1. **Cross-origin iframe чата Twitch недоступен для инъекции** — только внешние приёмы (двигать iframe / перекрывать). Синхронизация с внутренними виджетами невозможна.
2. **Hover-действия списка сообщества недоступны в Twitch Embed в принципе** — не тратить время на их «починку».
3. **Не воевать с сайтом через `display` на тике** — мерцание + сломанные клики. Использовать свойства, которые сайт не перезаписывает (`visibility`/`pointer-events`).
4. **Не доверять `beforeunload` для состояния между окнами** — heartbeat с таймаутом самовосстанавливается при любом закрытии.
5. **Проверять селекторы при работающем скрипте**, а не в вакууме — иначе правило заденет собственный виджет.
6. **Прежде чем чинить фичу — проверить, работала ли она хоть в одной версии и возможна ли в принципе** (экономит целые итерации).
